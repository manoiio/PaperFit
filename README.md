# PaperFit · 论文有格

产品现在只有两个主要入口，共用原检查、修正、预演和文件保护：

- **智能排版（推荐）**：上传 → 开始智能排版 → 下载。需要时使用AI辅助理解有限摘录；无必要候选不请求。只在原页面集中询问真正需要的例外。
- **本地精细工作台**：五步结构，自己控制规则、范围、选择和预演，**默认0API，不用密钥也能完成处理**。联网解析/结构工具仍可选，只有明确点击发送才请求。

智能入口现在可选择**当前要求、上传格式要求TXT/DOCX、使用已保存要求**。上传老师的要求后直接点击开始：仅明确、受支持的字段覆盖当前要求，未提及属性继续沿用；文件不等于已完整执行另一学校全部规范。提取保留TXT行号、DOCX段落/单元格位置和文件哈希；原文可展开查看，超过单次预算整份拒绝，不截取前几页。文件与文字补充二选一。

完成后点**“保存这套排版要求”**；下次选择“使用已保存的要求”上传该文件，点击开始即可本地验证并复用，**省去一次规范解析请求**。同一规则包也可导入本地精细工作台；不含论文、分类、旧修改授权或密钥。新论文若存在结构歧义仍可能需要结构API。背景、冲突、未支持和未提取内容分开处理；必要时只在主页面一次取舍，不逐字段确认。

第49阶段：新上传文档的摘要区域可在可靠章号＋标题样式/大纲处结束，缺少关键词不会继续吞入正文。同一份结构依据供分类、页码、章名页脚及动态范围复用；必要起点只集中询问一次。新增明确组合选择“完整整理：格式、编号同步、分区页码和章节页脚”，原方案/默认不变。常见页码说法本地证明，需语义提取时与格式要求共用一次短ID请求；只覆盖明确区域，未提及区域保持。未知起始值、早期未定标题或冲突仍询问，不猜1或物理页号。[阶段验收](docs/acceptance/phase49.md) · [真实下载、实网与Word证据](samples/phase49/README.md)。

第48阶段增加明确可选的**完整整理**：普通格式 → 安全题注编号/唯一纯文本引用同步 → 分节页码与章节页脚 → 最终复查。默认“常规格式整理”继续保持原有页码和编号。选择完整方案后，点击开始即授权当前安全操作集合，不再逐层启用动态、声明、预演及采用；无法证明完整的编号组保留并说明，不能因此声称全部引用已同步。[能力矩阵及真实Word记录](docs/acceptance/phase48.md) · [公开8页样本、规则、结果包及独立核对](samples/phase48/README.md)。

页码方案支持整个封面区域不显示、前置小写/大写罗马、正文指定值重启与后续连续或每章重启；页脚可为PAGE、已确认章节名称＋PAGE或普通文字＋PAGE，居中/居右。本地第5步可配置分区、保留区域、逐项真实预演采用或明确方案批量处理，默认零API。安全普通段落边界可新增分节，不插入段落、不重排原对象；共享页脚按默认/首页/偶数变体独立克隆。图形、复杂域、混合PAGE文字、页眉PAGE等冲突继续保护，不清空既有页脚。仅章节页脚策略不顺带改封面或编号格式。

可由本地连续原文可靠证明的页码、章节页脚、编号同步要求可直接处理，文字或TXT/DOCX均不必为这些确定声明请求AI；其他未消费要求仍走原严格解析。可复用规则包只存策略，本篇分区留在项目草稿。生成PAGE不等于更新目录、REF/PAGEREF或SEQ；本阶段没有Word COM或任意域刷新。

第47阶段：[通用段落能力、两入口及动态后续处理验收](docs/acceptance/phase47.md) · [公开组合样本与独立复现](samples/phase47/README.md)。支持值、实际渲染与Word观察分别记录，不把声明值通过当作实际分页合格。

第46阶段：同一固定16字段要求分别通过TXT/DOCX两次真实API，均实际修正并下载；规则复用不再请求规范解析。三条下载与同规则、范围、选择的原合法路径同字节，未触及配置和来源保持。[验收与限制](docs/acceptance/phase46.md)、[可公开证据和复现](samples/phase46/README.md)。

原快捷页已融合进本地工作台，没有第三套独立导航。第2步提供本地批量范围建议/一次核对检查，第3步提供核对全部安全项后的本地批量修正；逐项选择、单/合法两步预演及明确采用仍保留。第5步保留结果、历史、项目及默认关闭的动态入口；宽度、分页、重复表头、位置辅助和真实页面预览仍在原对应区域。切入口只导航，不执行、不切输入，不恢复旧授权。

智能入口现在自动准备**普通内容表格R23、Word脚注R36和尾注R37**的安全范围。表格优先本地库存/邻接题注证据；有价值的用途歧义与段落候选合并在一次有限摘录请求中（最多40候选、24000字符）。身份表、代码/敏感线索、合并/嵌套/浮动/条件样式等不因AI建议放开。脚注/尾注通过实际关系和类型本地定位，不发给AI；系统标记及复杂片段仍按原引擎保护。已有人工范围、明确关闭优先；旧恢复任务无法证明是新范围时保守保持。

使用项目所附**SCUT本科工理类2015年演示材料**，不宣称现行通用校规。只启用当前有实际要求的属性，不把正文要求套给表格/注释，也不补未配置值。封面、目录和复杂对象的自动处理范围没有扩大。部分范围处理成功不等于全文合格。

智能补充文字及TXT/DOCX要求文件现在支持通用段落声明：**倍数、固定磅值、最小磅值行距**；段前后（磅/行）、对齐；正文/摘要的首行字符或物理缩进，以及普通参考文献条目的明确悬挂。标题、图表题、摘要、关键词段、附录/致谢、脚注尾注按[支持矩阵](docs/acceptance/phase47.md)挂载；不把每种属性强加给所有对象。可直接写“正文固定20磅行距，首行缩进0.74厘米；一级标题段前12磅；参考文献最小20磅行距，悬挂缩进两字符”。仅覆盖原文明确字段，未提及值及来源保持；“行距20磅”缺少模式、“全文”范围不明、未知字体和润色不会猜测执行。原文字体/字号、表内文字、A4及边距能力保持。无补充不解析SCUT；有补充最多一次解析，结构识别最多另一次；失败集中取舍，不自动重试。

表格结构请求现在保留最多3行×3单元格、每格60字符的片段及前后/章节信息。证据必须定位到具体发送片段。隐藏、身份、代码、复杂及人工保护内容不因补充上下文被放开；待查看与下载不请求API，脱敏不保证彻底匿名。

**第45阶段已修通真实API到下载：原16字段补充与普通表格结构建议均实际参与排版。**模型返回短字段/来源/证据ID，本地补齐准确来源并执行原严格校验，不让用户修JSON。共3次合成实网请求；一次结构响应的多证据ID先被隔离，经零API重放定位和逐ID适配后验证通过。无补充不重复解析学校规则，不自动重试。两个浏览器下载均与同规则、范围、选择的原合法路径逐字节一致。短标题层级和用途不明的小表仍集中询问，不能以协议通过代表分类准确或全文合格。详见[第45阶段记录](docs/acceptance/phase45.md)与[可公开重放及文件证据](samples/phase45/README.md)。第44阶段未保存原响应，其历史失败仍只按[当时记录](docs/acceptance/phase44.md)描述；[第43阶段历史调用缺口](docs/acceptance/phase43.md)保持未知。

第47阶段增加共享段落属性读写与精确保护，未新增规则编号、Word COM或目录/域/真实页码刷新能力。旧数字行距仍为倍数；新模式和值明确保存，题注行距用v7模板、注释新增段落属性用v2补充配置，旧包仍可载入且不自动启用新字段。

**旧的逐项动态处理默认关闭，继续保留**：智能排版完成页与本地工作台第5步共用同一入口。在单文档扩展模式，明确声明相关题注范围完整后，可预演普通题注按章连续编号及唯一正文纯文本引用同步，再明确采用。只改授权数字，不改标题、run格式、图表或字段；重复目标、不可靠章节和复杂关联组不执行。**Windows Word COM适配及真实REF/PAGEREF、分页、目录页码更新本版尚未实现/验收**，当前macOS准确降级为需在Word更新并复核，不写`updateFields`冒充完成。

第四十阶段快捷/动态事务及真实浏览器的历史证据见[第四十阶段验收](docs/acceptance/phase40.md)与[文件索引](samples/phase40/README.md)。旧CLI、普通格式白名单和旧项目默认行为保持；动态是独立精确文本事务，不放松原格式保护。LibreOffice预览不是Word分页验收，0格式问题仍不等于全文合格。全量工作流现为**workflow_dispatch手动触发**，本阶段不触发远端全量，以本地实际结果报告。

原始响应只在显式公开合成调试中保留，默认不保存论文摘录或完整响应。离线诊断可用 `python scripts/reproduce_api_protocol.py --output /tmp/paperfit45-replay`，硬拦截网络，区分实网、已收响应重放和模拟。

## 安装与运行

Python 3.11+；开发环境为macOS/Python3.14。使用项目虚拟环境：

```bash
git clone https://github.com/manoiio/PaperFit.git
cd PaperFit
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/run_offline_tests.py
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

访问 http://127.0.0.1:8501 。Windows可将`.venv/bin/python`替换为`.venv\Scripts\python.exe`。本轮验收及环境见[阶段记录](docs/acceptance/phase48.md)，未实际验证的平台不宣称通过。

**源码仓库无需本机历史产物即可运行全部自动测试。** 必要合成文件在[tests/fixtures/history](tests/fixtures/history/README.md)，日常测试输出使用独立临时目录。测试不调用付费API，模拟预览不证明视觉排版；真实渲染、浏览器和Word记录分别报告。`work/`、`outputs/`、学校PDF、组员资料、真实论文和本机`.env`不进Git，不要求从别人机器复制这些目录。

## 智能主流程

1. 上传DOCX，页面显示当前SCUT演示要求；如需调整，填写受支持的多对象补充要求，或上传TXT/DOCX要求文件。
2. 点击“开始智能排版”。没有必要例外时自动完成；有疑问时在同一页面集中选择、确认继续，也可暂不处理该对象。
3. 点击“下载修正版”。同时查看主要调整与仍需留意的事项；完整结果包及技术记录按需展开。

这个命令不自动切换当前处理输入。可靠范围以外的对象、未配置属性及复杂结构不变成“通过”。相同有效命令的重复点击/重运行不会重复请求或登记轮次。原快捷能力已迁入本地工作台第2、3步，不再保留独立旧页面。

```bash
python scripts/reproduce_context_workflow.py --output /tmp/paperfit44-result
```

离线命令只用仓库现有合成样本、作者标注及模拟响应；与原合法路径逐字节对照，并独立核对ZIP/XML。可加`--browser-zip samples/phase44/controlled-result.zip`验证已归档真实浏览器下载，不调用API、Word或渲染器，不依赖本机历史目录。

在本地第5步点击“可选：动态编号与引用同步”后，核对章号/目标、完整题注范围及阻止组 → 生成真实动态预演 → 查看数字清单 → 确认采用。先普通格式、后动态文本；当前输入保持，只有明确继续才切换。旧入口不处理页码或目录；可选完整方案的页码由独立结构事务生成，不刷新引用域或目录。

```bash
python scripts/reproduce_smart_workflow.py --output /tmp/paperfit40-result
```

该命令使用仓库合成文件，对照原合法路径和作者手写XML预期，输出普通/动态副本、记录、结果包与项目。无需API、Word、渲染器或历史work/outputs；输出目录须不存在。

## 本地精细工作台（五步，默认不联网）

1. **文档与要求**：上传DOCX、使用内置合成样本或恢复项目。文件卡持续显示当前输入、轮次和规则。默认使用当前规则；选择“导入规则包 / 编辑规则”或“AI解析公开规范”才显示详细工作台。检查模式、更多样本和旧兼容入口在次要区域。选择模块与对象，在同一表单连续修改字体、字号、行距等实际支持属性，再点击“保存本对象的N项改动到草稿”。只保存真实改动；一个字段无效时整组不写入，输入仍可修复。“采用方式、来源与候选”可逐属性选择手动、保留当前、不检查或合法提取值；未触碰字段保持来源。“放弃本对象未保存改动”只恢复本对象缓冲，其他对象保留。高级单字段编辑共用同一草稿和缓冲。最后核对整份差异、“核对并应用整份规则”才生效；未保存控件会阻止整体应用，也不会写入项目包。
2. **确认检查范围**：查看按模块区分的配置、启用、纳入、排除和待核对状态；点击“进入核对”只打开该区域。段落核对可筛选/分页选择稳定编号、查看完整文本及相邻段落，区分原建议与当前草稿；可保存本段分类并返回总览，仍不等于范围确认。保护材料只读，批量分类不会覆盖。也可先用“本地批量范围建议”，核对摘要后一次接受并检查。精细路径继续核对完整摘要、材料保护和部分范围声明，再明确勾选并点击“确认这些范围并开始检查”。原分区域确认/独立检查保留在高级区域。
3. **查看问题**：分别显示问题、可修正、只读和待复核；常用筛选与“更多筛选”分开。左侧默认显示本页最多20个对象、短文本、混合状态数量及已选数；右侧每页最多4条检查项，查看“实际 → 要求”后明确“加入修正 / 移出修正”。点击对象和检查项只查看，不授权修正。“已选 N 项 · 查看清单”包含其他页和筛选外选择，每页8项，可逐项移除；预演包含全部已选项。批量入口分别标明本页、当前筛选全部页、当前输入全部可修正项及数量，均需明确操作。清除筛选不清选择，返回问题页保留有效查看位置；不默认全选。“本地批量修正当前安全项”可核对全部安全方案后一次明确授权修正；与手工已选清单区分，不暗中加入选择。宽度、分页和位置辅助仍在对应操作区域，原始覆盖与只读关系明细按需展开。
4. **修正预演**：先看实际修改、关键影响与前后值，完整选择及来源按需展开；核对当前输入、全部选择及依赖；单轮使用“预演所选修正”，有已知依赖时显示原两步计划。查看实际修改、自然符合、新问题及待复核变化，明确核对并采用，才登记正式副本。返回修改选择后须重新预演；采用不等于视觉验收。
5. **结果与下载**：首屏提供正式DOCX与结果包，并显示剩余问题、待复核和当前输入。“查看本轮页面 / 与原稿对比”只进入阅读区；无页图时明确生成，已有有效页图优先显示。阅读区可切单份/并排、文件和页码；不同页数、没有对应页与超出前10页范围分别说明，同页号不等于内容自动对齐。辅助操作及预览环境、字体映射、人工记录在次级入口；“返回结果与下载”可取走成果。采用后**当前输入仍保持**，只有明确点击“以本轮修正版开始下一轮”或“以计划最终副本继续”才切换。

切页保留业务草稿、材料排除和明确修正选择；尚未提交的规则编辑仅保留为本会话编辑缓冲，不生效。确认勾选不跨视图恢复为授权，快照改变仍需重新核对。各步骤可返回，返回不代表流程重新开始。第一次载入显示尚未检查；只有当前会话确实观察过对应输入的检查，随后不可用时才提示原检查不可用，不猜具体原因。这项UI观察记录不随项目恢复成为旧授权。最新正式记录须核对轮次和内容哈希才标为当前输入；查看历史或预览文件不切换输入。恢复项目后依据真实状态重新显示，不恢复旧预演授权。

规则包用于跨文档复用格式要求，不含DOCX、对象编号、范围或历史。项目ZIP用于中断后继续，**包含论文原稿和副本**，恢复前须核对，恢复后实际重新检查。原始文件、前轮输出和已存在目标均拒绝覆盖。

## 第三十二阶段：内部引用结构与安全内部链接文字

在单文档模式展开**内部书签、超链接与交叉引用**，明确启用R44，可筛选目标、状态及分页清单。按部件/故事/段落或XML位置读取书签ID、名称、边界、普通anchor、REF/PAGEREF简单及复杂域。名称精确匹配，支持常见ASCII/下划线名称（最长40字符），不丢弃系统书签。重复名称、大小写近似、异常边界、未知开关及不完整故事清单保留待复核；不猜目标、不更新域。PAGE/SEQ/STYLEREF只列指令，不当作书签引用。

一个缺失目标可影响多个引用位置，报告分别计数，目录使用同一目标证据；不能相加为独立故障。清单不足时不判确定缺失或授权内部链接文字修正。未引用的有效书签不判错，没有引用不算缺项。**目标存在不等于缓存新鲜、引用正确、实际页码或真实跳转已验收。**

另行明确勾选**同时允许安全内部链接文字格式检查与选项修正**，只开放anchor单一目标、边界有效且直属普通run的链接，执行原已确认对象的配置属性。文字、anchor、链接属性、关系、字符样式、未选颜色/下划线保持；缺失或含糊目标、r:id/docLocation组合、自动目录缓存、域、SDT、修订仍只读。表格/页眉页脚链接文字、含链接段落属性、R11及R33边界未扩大。沿用明确选择→预演→核对采用→另存/复查/下一轮；可导出补充JSON、报告和结果ZIP，项目恢复后重新索引检查。

[完整验收及官方出处](docs/acceptance/phase32.md) · [原稿、独立对照、实际输出、报告、截图与索引](samples/phase32/README.md) · [离线复现](scripts/reproduce_internal_reference_demo.py) · [独立ZIP/XML核对](scripts/verify_internal_reference_output.py) · [索引成本测量](scripts/measure_internal_references.py)。合成样本5处所选字号修正后仍保留3条规则问题/44条待复核，含1个目标故障影响3处引用；不是全文合格。所有检查不访问网络、不计算域、0新增AI、0自动渲染。

## 第三十一阶段：引文上标段落的安全段落属性

已确认正文及引文用途后，仅当所有特殊上标字符都精确落在确认引文区间内，才放行R06倍数行距、R07首行缩进和已配置R13段前/段后/对齐。网页“已确认引文上标 · 段落属性判定证据”显示原文区间、普通正文依据、允许属性和仍待复核原因。部分范围也可局部判断，不自动声明全文完整。

R07点值换算仅用引文之外的可靠普通正文；引文字号和上标缩放不参与。只有引文而没有正文依据的点值缩进仍待复核。基线空白不作字号依据，引文外上标空白也不能豁免。未确认上标、下标、区间外上标、链接、域、书签、自动编号、网格及原有继承/单位保护保持；引文自己的字体字号仍不套正文。

选择 → 预演 → 核对影响 → 采用 → 下载/下一轮，继续使用原pPr事务。普通格式→R33两步计划完成后，未选缩进仍会重新检查且不会自动修改。项目恢复重新检查，不恢复预演授权；执行绑定包含新增判定代码。没有新增规则、模板字段、AI调用或自动渲染。

## 第三十阶段：组合与区间引文

单文档模式启用引文后，默认仍是v1单整数`[1]`。在**明确切换引文语法版本**核对差异并升级v2，支持`[1,3]`、`[1-3]`、`[1–3]`、`[1-3,5]`及普通ASCII空格。候选仍须明确确认为引文或排除数组；升级不确认范围、不声明完整、不授权修正。

v2限制：编号1–99999，单组最多512字符，累计最多100个展开成员（重复/重叠也计入）。全角括号、中文逗号、其他连接符、倒序和异常表达只读。保留完整原文、成员/区间位置、展开及唯一编号，不转换文字。支持语法是产品能力，不冒充学校明示的表达形式。

R34逐个唯一编号显示对应结果：`[1,14]`不会因为1存在就整组通过。首次顺序按**出现位置组**及累计编号集合连续性作产品解释：同位置`[2,1]`不因组内排列报跨位置违规；`[1,3]`后才出现`[2]`保留3早于2的证据。部分范围、未确认候选或编号未知仍待复核；重复/重叠与未引用条目仅核对提示。

R33只将所选完整字符组设为上标，不改字号、字体或编号。链接、域、书签等保护不变；同段普通格式和引文拆分仍通过已有两步计划，采用时0次完整重修。语法配置、草稿、范围、预演、项目恢复、逐成员报告和结果ZIP保持绑定；旧配置/旧项目不会自动升级。

## 第二十九阶段：普通超链接文字

正文只扩大R03/R04/R05；参考文献仅执行已配置文字属性；注释仅中文字体与字号。颜色、下划线、字符样式、关系和未选属性保持。含链接段落的行距/缩进/段距、R11样式修改及R33继续保护；阶段29当时不支持内部anchor；阶段32仅明确启用后扩大普通anchor文字。域/自动目录、嵌套SDT、修订、无效关系、表格及页眉页脚链接保护保持。网页外部关系预览限制保持，真实本地渲染QA和Word观察分别记录。

## 第二十八阶段：已知依赖的分步计划

同段普通run字体字号与R33仍不能同轮直接修正。现在可在一份明确选择中核对最多两步：先普通格式，再从实际副本的新检查按段落身份及字符范围定位引文。每步走原事务与落盘复查，不复用旧run编号、不搜索同名文本任意匹配，也不自动追加新问题。没有跨步依赖仍用原单轮预演。

预演不增加正式轮次、不切换输入。查看每步及整个计划的影响后，一次采用全部已验证副本；先校验并准备全部归档，失败不发布半计划，重复点击不重复登记。采用0次完整修正，每步副本可独立下载；结果ZIP含最终DOCX和各步修改/复查，中间DOCX不默认打包。项目恢复选择意图与历史，不恢复临时副本或执行授权。

## 第二十七阶段：预演与确认复用

预演调用原修正器与落盘复查；不调用AI、不自动渲染，不登记正式历史。实际修改记录、XML属性数量与检查记录变化分别显示，例如只改字号也可能自然解决未选R07，或引出新的缩进问题。新问题不自动加入选择，问题转待复核不算解决；必要run拆分不能可靠对齐时明确保留记录。

## 第二十五阶段：诊断与本地修复

统一解析保留规范快照及哈希、完整模型文字、结束状态和脱敏回执。旧严格解析接口仍整稿拒绝非法结果；网页显式使用独立的非执行诊断接口：

- 网络/协议、非法JSON、重复键、工具调用、截断、未知模块或执行字段：整份拒绝，不能补JSON或删危险字段来执行。
- 完整JSON的已知字段/提示错误：一次列出独立诊断、合格候选、隔离字段和未提及内容。错误issue的已知影响字段继续隔离，范围未知则保守隔离模块。
- 唯一来源映射须同时验证原行号与连续原句、显示范围并由用户明确采用；重复原句、多个来源不猜测。
- 可以修正连续原句、提示关联，或明确手动取舍/不检查。原响应保持，修复记录含理由；修复字段最终是用户确认值，不能冒充原始AI结果。
- 全量重新校验后才能转入原规则草稿；未提及策略不处理隔离字段。最后仍需整体差异确认与原子应用，对象范围另行核对。

“解析诊断与本地修复”提供公开合成失败夹具，**没有API请求**。修复、筛选、下载、重运行和恢复均不请求AI。修改摘录后，旧诊断只保留历史，不能直接绑定新摘录。单响应64KB、单诊断256KB、最多100项修复、3份历史及1MB存储；满额须明确导出/清理，不静默截断。疑似密钥/私人路径不保存原文，记录拒绝摘要。

详细诊断可单独导出，含规范快照与不可信响应；规则包不会默认携带这些失败日志。项目可以恢复未应用修复草稿，但会重新校验并标记历史，不自动应用或请求API。
