# PaperFit · 论文有格

当前智能入口支持**可选AI辅助结构识别**：沿用本地SCUT/已生效要求 → 查看待发送有限摘录 → 一次明确DeepSeek请求 → 本地校验并合并范围建议 → 接受摘要检查 → 一键智能修正下载。无需AI也可直接沿用原本地流程；AI不自动确认对象、不授权修正、不替代复杂结构保护。当前basic/extended/academic角色集合不同，不自动换模式或开启模块。

相同有效输入和配置复用本会话结果；查看、检查、修正、下载、项目恢复不触发API。项目只保存原有已接受分类，不保存结构请求摘录、缓存或授权。真实小样本8候选中7项与独立标注一致、1项标题层级错误，经人工纠正后下载与原合法路径同字节；这不是总体准确率。**Word COM、目录/域更新和实际页码核验没有新增。** [第41阶段验收](docs/acceptance/phase41.md) · [合成文件与复现](samples/phase41/README.md)。

本地单文档DOCX格式检查与安全修正课程Demo。规则来源是项目2015年学校演示材料或用户确认的自定义规范，不宣称现行通用校规。检查范围由用户确认；格式通过不等于目录页码准确、引用真实或全文排版合格。

当前默认入口是**智能处理**：上传论文并沿用生效要求 → 自动显示保守范围建议 → 接受摘要并检查 → **一键智能修正** → 下载与剩余事项。无需逐段分类或逐项勾选即可处理可靠范围。人工草稿/材料保护优先，歧义、未配置及未准备的可选区域明确保留。点击一键按钮授权展示的安全方案；内部复用原真实预演、落盘复查和采用，采用不重复修正，也不自动切换当前输入。

原**五步详细工作区**完整保留，用于规则草稿、多属性编辑、例外范围、逐项选择、单轮/两步预演及页面阅读。顶部五步按钮进入详细操作，“智能处理”可返回快捷入口；导航本身不执行处理。AI只在明确解析规范时调用，智能格式处理在本机使用当前规则，不把论文发送给API。

**可选动态处理默认关闭**：在单文档扩展模式，明确声明相关题注范围完整后，可预演普通题注按章连续编号及唯一正文纯文本引用同步，再明确采用。只改授权数字，不改标题、run格式、图表或字段；重复目标、不可靠章节和复杂关联组不执行。**Windows Word COM适配及真实REF/PAGEREF、分页、目录页码更新本版尚未实现/验收**，当前macOS准确降级为需在Word更新并复核，不写`updateFields`冒充完成。

原1227项场景继续保留，新增快捷/动态事务及真实浏览器证据见[第四十阶段验收](docs/acceptance/phase40.md)与[文件索引](samples/phase40/README.md)。旧CLI、普通格式白名单和旧项目默认行为保持；动态是独立精确文本事务，不放松原格式保护。LibreOffice预览不是Word分页验收，0格式问题仍不等于全文合格。全量工作流现为**workflow_dispatch手动触发**，本阶段不触发远端全量，以本地实际结果报告。

## 安装与运行

Python 3.11+；开发环境为macOS/Python3.14。使用项目虚拟环境：

```bash
git clone https://github.com/manoiio/PaperFit.git
cd PaperFit
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

访问 http://127.0.0.1:8501 。Windows可将`.venv/bin/python`替换为`.venv\Scripts\python.exe`。本轮验收及环境见[阶段记录](docs/acceptance/phase40.md)，未实际验证的平台不宣称通过。

**源码仓库无需本机历史产物即可运行全部自动测试。** 必要合成文件在[tests/fixtures/history](tests/fixtures/history/README.md)，日常测试输出使用独立临时目录。测试不调用付费API，模拟预览不证明视觉排版；真实渲染、浏览器和Word记录分别报告。`work/`、`outputs/`、学校PDF、组员资料、真实论文和本机`.env`不进Git，不要求从别人机器复制这些目录。

## 智能主流程

使用当前生效要求的常见流程实际为4次主要操作：上传 → 接受自动摘要并检查 → 一键智能修正 → 下载。修改规则、处理例外及动态采用是独立任务，不计入这4次；没有安全修正项时不生成新轮次。可选对象未准备时在摘要列为未纳入，不要求用户宣称全文完整。

点击“可选：动态编号与引用同步”后，核对章号/目标、完整题注范围及阻止组 → 生成真实动态预演 → 查看数字清单 → 确认采用。先普通格式、后动态文本；当前输入保持，只有明确继续才切换。页码、域及目录仍须Word更新，不插入新目录。

```bash
python scripts/reproduce_smart_workflow.py --output /tmp/paperfit40-result
```

该命令使用仓库合成文件，对照原合法路径和作者手写XML预期，输出普通/动态副本、记录、结果包与项目。无需API、Word、渲染器或历史work/outputs；输出目录须不存在。

## 五步详细流程（兼容与例外处理）

1. **文档与要求**：上传DOCX、使用内置合成样本或恢复项目。文件卡持续显示当前输入、轮次和规则。默认使用当前规则；选择“导入规则包 / 编辑规则”或“AI解析公开规范”才显示详细工作台。检查模式、更多样本和旧兼容入口在次要区域。选择模块与对象，在同一表单连续修改字体、字号、行距等实际支持属性，再点击“保存本对象的N项改动到草稿”。只保存真实改动；一个字段无效时整组不写入，输入仍可修复。“采用方式、来源与候选”可逐属性选择手动、保留当前、不检查或合法提取值；未触碰字段保持来源。“放弃本对象未保存改动”只恢复本对象缓冲，其他对象保留。高级单字段编辑共用同一草稿和缓冲。最后核对整份差异、“核对并应用整份规则”才生效；未保存控件会阻止整体应用，也不会写入项目包。
2. **确认检查范围**：查看按模块区分的配置、启用、纳入、排除和待核对状态；点击“进入核对”只打开该区域。段落核对可筛选/分页选择稳定编号、查看完整文本及相邻段落，区分原建议与当前草稿；可保存本段分类并返回总览，仍不等于范围确认。保护材料只读，批量分类不会覆盖。然后核对完整摘要、材料保护和部分范围声明，再明确勾选并点击“确认这些范围并开始检查”。原分区域确认/独立检查保留在高级区域。
3. **查看问题**：分别显示问题、可修正、只读和待复核；常用筛选与“更多筛选”分开。左侧默认显示本页最多20个对象、短文本、混合状态数量及已选数；右侧每页最多4条检查项，查看“实际 → 要求”后明确“加入修正 / 移出修正”。点击对象和检查项只查看，不授权修正。“已选 N 项 · 查看清单”包含其他页和筛选外选择，每页8项，可逐项移除；预演包含全部已选项。批量入口分别标明本页、当前筛选全部页、当前输入全部可修正项及数量，均需明确操作。清除筛选不清选择，返回问题页保留有效查看位置；不默认全选。宽度、分页和位置辅助仍在对应操作区域，原始覆盖与只读关系明细按需展开。
4. **修正预演**：先看实际修改、关键影响与前后值，完整选择及来源按需展开；核对当前输入、全部选择及依赖；单轮使用“预演所选修正”，有已知依赖时显示原两步计划。查看实际修改、自然符合、新问题及待复核变化，明确核对并采用，才登记正式副本。返回修改选择后须重新预演；采用不等于视觉验收。
5. **结果与下载**：首屏提供正式DOCX与结果包，并显示剩余问题、待复核和当前输入。“查看本轮页面 / 与原稿对比”只进入阅读区；无页图时明确生成，已有有效页图优先显示。阅读区可切单份/并排、文件和页码；不同页数、没有对应页与超出前10页范围分别说明，同页号不等于内容自动对齐。辅助操作及预览环境、字体映射、人工记录在次级入口；“返回结果与下载”可取走成果。采用后**当前输入仍保持**，只有明确点击“以本轮修正版开始下一轮”或“以计划最终副本继续”才切换。

切页保留业务草稿、材料排除和明确修正选择；尚未提交的规则编辑仅保留为本会话编辑缓冲，不生效。确认勾选不跨视图恢复为授权，快照改变仍需重新核对。各步骤可返回，返回不代表流程重新开始。第一次载入显示尚未检查；只有当前会话确实观察过对应输入的检查，随后不可用时才提示原检查不可用，不猜具体原因。这项UI观察记录不随项目恢复成为旧授权。最新正式记录须核对轮次和内容哈希才标为当前输入；查看历史或预览文件不切换输入。恢复项目后依据真实状态重新显示，不恢复旧预演授权。

规则包用于跨文档复用格式要求，不含DOCX、对象编号、范围或历史。项目ZIP用于中断后继续，**包含论文原稿和副本**，恢复前须核对，恢复后实际重新检查。原始文件、前轮输出和已存在目标均拒绝覆盖。

## 第三十二阶段：内部引用结构与安全内部链接文字

在单文档模式展开**内部书签、超链接与交叉引用**，明确启用R44，可筛选目标、状态及分页清单。按部件/故事/段落或XML位置读取书签ID、名称、边界、普通anchor、REF/PAGEREF简单及复杂域。名称精确匹配，支持常见ASCII/下划线名称（最长40字符），不丢弃系统书签。重复名称、大小写近似、异常边界、未知开关及不完整故事清单保留待复核；不猜目标、不更新域。PAGE/SEQ/STYLEREF只列指令，不当作书签引用。

一个缺失目标可影响多个引用位置，报告分别计数，目录使用同一目标证据；不能相加为独立故障。清单不足时不判确定缺失或授权内部链接文字修正。未引用的有效书签不判错，没有引用不算缺项。**目标存在不等于缓存新鲜、引用正确、实际页码或真实跳转已验收。**

另行明确勾选**同时允许安全内部链接文字格式检查与选项修正**，只开放anchor单一目标、边界有效且直属普通run的链接，执行原已确认对象的配置属性。文字、anchor、链接属性、关系、字符样式、未选颜色/下划线保持；缺失或含糊目标、r:id/docLocation组合、自动目录缓存、域、SDT、修订仍只读。表格/页眉页脚链接文字、含链接段落属性、R11及R33边界未扩大。沿用明确选择→预演→核对采用→另存/复查/下一轮；可导出补充JSON、报告和结果ZIP，项目恢复后重新索引检查。

## 第三十一阶段：引文上标段落的安全段落属性

已确认正文及引文用途后，仅当所有特殊上标字符都精确落在确认引文区间内，才放行R06倍数行距、R07首行缩进和已配置R13段前/段后/对齐。网页“已确认引文上标 · 段落属性判定证据”显示原文区间、普通正文依据、允许属性和仍待复核原因。部分范围也可局部判断，不自动声明全文完整。

R07点值换算仅用引文之外的可靠普通正文；引文字号和上标缩放不参与。只有引文而没有正文依据的点值缩进仍待复核。基线空白不作字号依据，引文外上标空白也不能豁免。未确认上标、下标、区间外上标、链接、域、书签、自动编号、网格及原有继承/单位保护保持；引文自己的字体字号仍不套正文。

选择 → 预演 → 核对影响 → 采用 → 下载/下一轮，继续使用原pPr事务。普通格式→R33两步计划完成后，未选缩进仍会重新检查且不会自动修改。项目恢复重新检查，不恢复预演授权；执行绑定包含新增判定代码。没有新增规则、模板字段、AI调用或自动渲染。

## 第三十阶段：组合与区间引文

单文档模式启用引文后，默认仍是v1单整数`[1]`。在**明确切换引文语法版本**核对差异并升级v2，支持`[1,3]`、`[1-3]`、`[1–3]`、`[1-3,5]`及普通ASCII空格。候选仍须明确确认为引文或排除数组；升级不确认范围、不声明完整、不授权修正。

v2限制：编号1–99999，单组最多512字符，累计最多100个展开成员（重复/重叠也计入）。全角括号、中文逗号、其他连接符、倒序和异常表达只读。保留完整原文、成员/区间位置、展开及唯一编号，不转换文字。支持语法是产品能力，不冒充学校明示的表达形式。

R34逐个唯一编号显示对应结果：`[1,14]`不会因为1存在就整组通过。首次顺序按**出现位置组**及累计编号集合连续性作产品解释：同位置`[2,1]`不因组内排列报跨位置违规；`[1,3]`后才出现`[2]`保留3早于2的证据。部分范围、未确认候选或编号未知仍待复核；重复/重叠与未引用条目仅核对提示。

R33只将所选完整字符组设为上标，不改字号、字体或编号。链接、域、书签等保护不变；同段普通格式和引文拆分仍通过已有两步计划，采用时0次完整重修。语法配置、草稿、范围、预演、项目恢复、逐成员报告和结果ZIP保持绑定；旧配置/旧项目不会自动升级。

## 第二十九阶段：普通超链接文字

## 第二十八阶段：已知依赖的分步计划

同段普通run字体字号与R33仍不能同轮直接修正。现在可在一份明确选择中核对最多两步：先普通格式，再从实际副本的新检查按段落身份及字符范围定位引文。每步走原事务与落盘复查，不复用旧run编号、不搜索同名文本任意匹配，也不自动追加新问题。没有跨步依赖仍用原单轮预演。

预演不增加正式轮次、不切换输入。查看每步及整个计划的影响后，一次采用全部已验证副本；先校验并准备全部归档，失败不发布半计划，重复点击不重复登记。采用0次完整修正，每步副本可独立下载；结果ZIP含最终DOCX和各步修改/复查，中间DOCX不默认打包。项目恢复选择意图与历史，不恢复临时副本或执行授权。

## 第二十七阶段：预演与确认复用

预演调用原修正器与落盘复查；不调用AI、不自动渲染，不登记正式历史。实际修改记录、XML属性数量与检查记录变化分别显示，例如只改字号也可能自然解决未选R07，或引出新的缩进问题。新问题不自动加入选择，问题转待复核不算解决；必要run拆分不能可靠对齐时明确保留记录。

采用前重新核对完整绑定、原白名单及实际报告，原子归档同一副本。重复确认只登记一轮。改变选择、范围、文件或规则使旧预演/勾选失效；取消只清理本会话临时副本。项目恢复选择草稿但不恢复预演授权，须重新检查和预演。高级直接生成仍使用同一引擎；宽度、分页和L05保持独立操作。

## 第二十六阶段：统一范围预检

各区域分别显示是否启用、有无要求、检测数量及口径、草稿选择、保护/排除、待核对、确认有效性和阻止项，不生成覆盖率或合格分数。没有发现对象不证明物理上没有；未启用、未配置、未确认及复杂结构都不会变成通过。

预检不改状态/文件，也不执行检查、修正、AI或预览。统一确认先验证全部范围和组合约束、成功存储后一次发布确认，再走原检查器。任一区域或存储失败不留下部分新确认。文件、规则或草稿改变，旧摘要勾选失效。报告、HTML和结果ZIP附真实范围摘要；项目恢复重建总览，不恢复旧勾选或视觉结论。

## 第二十五阶段：诊断与本地修复

统一解析保留规范快照及哈希、完整模型文字、结束状态和脱敏回执。旧严格解析接口仍整稿拒绝非法结果；网页显式使用独立的非执行诊断接口：

- 网络/协议、非法JSON、重复键、工具调用、截断、未知模块或执行字段：整份拒绝，不能补JSON或删危险字段来执行。
- 完整JSON的已知字段/提示错误：一次列出独立诊断、合格候选、隔离字段和未提及内容。错误issue的已知影响字段继续隔离，范围未知则保守隔离模块。
- 唯一来源映射须同时验证原行号与连续原句、显示范围并由用户明确采用；重复原句、多个来源不猜测。
- 可以修正连续原句、提示关联，或明确手动取舍/不检查。原响应保持，修复记录含理由；修复字段最终是用户确认值，不能冒充原始AI结果。
- 全量重新校验后才能转入原规则草稿；未提及策略不处理隔离字段。最后仍需整体差异确认与原子应用，对象范围另行核对。

“解析诊断与本地修复”提供公开合成失败夹具，**没有API请求**。修复、筛选、下载、重运行和恢复均不请求AI。修改摘录后，旧诊断只保留历史，不能直接绑定新摘录。单响应64KB、单诊断256KB、最多100项修复、3份历史及1MB存储；满额须明确导出/清理，不静默截断。疑似密钥/私人路径不保存原文，记录拒绝摘要。

详细诊断可单独导出，含规范快照与不可信响应；规则包不会默认携带这些失败日志。项目可以恢复未应用修复草稿，但会重新校验并标记历史，不自动应用或请求API。

## 可选DeepSeek配置

复制`.env.example`为本机`.env`并填写，或设置环境变量；不要把密钥发到聊天、URL或提交到Git：

```dotenv
DEEPSEEK_API_KEY=YOUR_DEEPSEEK_API_KEY
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

沿用已核对模型白名单与官方HTTPS接口。规范解析入口仅在明确点击时发送已核对的公开规范摘录及字段说明。另有第41阶段可选结构识别：明确点击发送按钮后，发送最多40个未确认歧义候选的脱敏短文本、有限邻段/章节锚点和样式信息；不上传DOCX、图片或全文，不重复解析SCUT要求。隐藏明显身份信息不等于彻底匿名。一次点击最多一次POST、约30秒超时，无自动重试。无配置或失败时默认和已确认模板仍可使用。历史结果不冒充实时解析。

## 可选本地页面预览

预览需要额外的Codex bundled文档运行时，不属于requirements.txt，也不是测试前提。默认从当前用户home查找现有运行时；可在启动前设置：

```bash
export PAPERFIT_PREVIEW_RUNTIME='/absolute/path/to/bundled/dependencies'
export PAPERFIT_PREVIEW_RENDERER='/absolute/path/to/documents/render_docx.py'
```

只有明确生成预览才探测环境并排队渲染，最多一个实际任务，保留同步接口；未安装时仅预览不可用，检查、修正和下载不受影响。不自动安装/控制桌面Office。字体替代可能改变分页；报告标记渲染器与字体，不冒充Word。默认前10页，历史预览不作为当前环境验证。
