# 附录与致谢合成样本

软件演示内容，没有真实作者或论文资料。

- `backmatter-errors.docx`：20个旧语义的顶层段落、一个普通表格、一张内嵌图片，两个附录及一个致谢。
- `backmatter-correct.docx`：仅就学校明示的新对象格式的正确对照，不宣称全文/目录/所有旧内容要求通过。
- `.types.json`：独立确认类型及人工材料排除，分别绑定各DOCX哈希；不是程序自动确认建议。
- `backmatter-expected-errors.json`：根据样本注入方式独立列出的14项附录格式错误位置，保留材料范围及目录目标线索。
- `norm22-B.txt`：公开合成自定义规范，包含附录、致谢要求及“代码/数据不适用”范围说明。不是学校原文。真实演示将提取的致谢12pt改为用户13pt后应用。

编号清单：8/15附录标题，9/10/17普通文献文字，18致谢标题，19/20致谢普通文字；7正文；11/12/13/14/16代码、数据、图表材料明确排除。表格单元格不插入旧段落编号。段10后半run使用独立字符样式。段7句中提及附录/致谢不应识别成章节。

目录3–6仅用于确认与对应演示，保存的1/2页码并未核对。目录“致谢”与章节“致 谢”保留差异；不能通过删空格掩盖。附录B标题后紧接代码，L03必须阻止；附录A及致谢后确认普通文字可提出安全建议。缺少摘要/文献时旧R22的范围提示保留，不通过这些样本声称全文格式合格。

生成脚本在`work/phase22/build_samples.py`，用bundled Python/docx创建。测试和浏览器使用同一实际样本，不预先写“修正成功”结论。所有修正版均由真实引擎另存产生。
