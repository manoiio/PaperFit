# 脱敏合成软件演示样本

第十五阶段另增 `academic-correct.docx`、`academic-errors.docx`及对应 `.types.json`：28个顶层段落，中英文摘要、跨run关键词标签、三级标题、正文、图表题注、10条虚构参考文献，一张图片、一个普通表格。使用显式“单文档扩展检查”模式；软件说明第2段应核对为其他。正确对照覆盖内0问题/0待复核，错误版18问题，独立作者清单为 `academic-expected-errors.json`。新增样本不改变下方旧样本的编号或验收语义。

`norm15-A.txt`、`norm15-B.txt`为软件演示规范，B体现按对象字体字号、行/磅间距、对齐、标签加粗及字符缩进的区别，含未支持打印要求。生成及最终验收详见 `outputs/phase15/验收记录.md`；0属性问题不表示分页全部合适。

两份DOCX包含完全相同的文字、图片和表格；作者、研究与表格数据均为虚构。只用于软件演示，不是实际课程论文或完整学位论文。

## 第四阶段扩展样本

`extended-correct.docx`、`extended-errors.docx`为本阶段新建的脱敏合成软件演示，保留原阶段所有样本。各有24个顶层段落、2节、1图、1表、一个PAGE域排除对象；包含三级标题、手工假标题、正文、图题、表题、数字句子、摘要、目录及参考文献排除案例。正确对照中第13段已用Heading2，错误版则手工格式外观相近，需R11检查。

`extended-expected-errors.json`为独立人工清单，共9问题，不从检查器输出推导。两份`.types.json`为样本作者逐段核对的完整类型；网页运行时仍按通用算法提出建议，并要求用户确认，不能用这些位置作为识别算法。

R11单选会保留未选有效格式，因此修正版手工标题的加粗等外观可能与对照不同；这些不是新增规则。自定义14pt/2倍会令第14段原24pt点值缩进不等效两字符，第一轮只报告新增R07，第二轮明确选择后写字符缩进。`build_extended_samples.py`可追溯生成逻辑，已有输出时拒绝覆盖。

## 第十六阶段表格文字样本

`table-text-correct.docx`、`table-text-errors.docx`保留28个顶层段落，包含7个独立顶层表格：1为封面/表单排版演示，2普通内容及多段单元格，3常见样式继承，4横向合并，5上角标/公式保护，6嵌套边界，7首行条件样式与直接覆盖。`.types.json`含独立 `table_scope`，不能把这些位置硬编码为通用用途识别。

作者按注入位置预写 `table-text-expected-errors.json`，5条确定错误；全部内容表格范围下错误版5问题/9待复核，对照版0问题/9待复核。复杂对象是刻意的边界，不称对照全文合格；只确认普通表2时为2问题/0待复核，修后0/0。单元格编号是行中实际XML对象，合并不虚拟重复。源文件仅软件演示，无真实作者资料。

## 第十七阶段封面与分节样本

`front-errors.docx`、`front-correct.docx`各4节/4页，仅为软件演示，含普通论文标题、封面表格、待填/重复字段候选、普通及共享故事、简单/复杂PAGE、罗马/阿拉伯配置和混合用途。`front-expected-errors.json`独立记录7项注入；对应`.types.json`含人工定位与用途，网页上传仍须确认。前置页眉居中来自用户补充要求，学校原文只规定主体页眉，不能串用出处。

对照仅说明本轮R24–R29没有确定格式问题。默认R22仍会提示短样本确认的参考文献不足；字段、连续性、实际分页及打印事项保留人工复核，不能把对照称作全文合格。生成器`python -m samples.build_front_samples`拒绝覆盖已有样本。副本、复查、真实浏览器下载及预览证据见`work/phase17/delivery`和`outputs/phase17/验收记录.md`。
