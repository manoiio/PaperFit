# 遇到问题时

先下载已经准备好的合法DOCX，必要时保存项目。不要发送API密钥、真实论文或未经脱敏的错误截图。

| 情况 | 可以怎样处理 |
|---|---|
| 网页打不开 | 双击“启动论文有格.command”，等待健康检查后打开8501。若提示依赖缺失，保留终端错误并联系维护人员；启动器不重建环境。 |
| 8501被占用 | 启动器只复用能证明属于本仓库且健康的服务。占用者不明时不会停止；请核对程序，勿盲目kill端口。维护人员确认属于本项目后才可重启，先保存项目。 |
| API未配置/请求失败 | 基础检查修正仍可使用，本地精细工作台默认零API。智能识别不确定的部分会保持或询问；不能理解的补充要求，可明确选择沿用当前模板或修改要求，不需重新上传。不会自动重试收费。 |
| Word权限不足/对话框阻塞 | 查看本机Word是否有本任务的权限或保存对话框，按系统提示处理；不要关闭其他文档。普通自检只查安装，深入检测才实际调用公开样本。 |
| Word超时 | 停止接收结果不等于Word已经停止。先确认本任务副本和对话框，相关任务结束后自行保存其他文档、退出Word，再点“检查并解除Word超时隔离”。程序不全局kill Word。 |
| PDF失败，但DOCX已完成 | 先下载DOCX。PDF是独立可选成果，失败原因见Word PDF状态。确认Word环境后明确重试生成，或到本地工作台选LibreOffice备用预览；不会把备用标成Word。 |
| 字体重影/缺字或分页不同 | 核对实际字体及加粗、效果要求。未明确要求的加粗/颜色不会自动清除；预览字体别名不写回DOCX。可在现有规则中明确修改后重新检查，不要盲目替换全部字体。Word与LibreOffice分别判断。 |
| 恢复项目后需重新开始 | 保存的是文件、规则和历史，不是持续有效的执行授权。重新检查/开始会验证当前哈希、范围和代码，恢复不会自动联网或控制Word。未保存的控件编辑不当作已保存草稿。 |
| 下载看到旧文件 | 核对首屏当前输入、最新正式输出和PDF源哈希；查看历史不会切换输入。新要求或范围变化后旧任务不可用于本次，重新开始前可先保存前轮成果。 |

本地技术自检：在仓库目录运行 `.venv/bin/python scripts/local_start.py --check`。明确使用公开样本探测Word/PDF：加 `--deep-word`。日志只记录启动时间、动作及端口；不记录密钥或论文内容。深入检测文件位于忽略的 `work/local/`，不进入Git或公开样例包。
