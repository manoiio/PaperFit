# 第57阶段：目录参考外观与明确收录集合

基线main/74acd9e。仅针对性验收；本轮没有完整unittest discover、远端CI、付费API或部署。

## 实现

- 新任务智能完整整理采用“项目参考样式”：固定23.7磅、段前后0、一级0/二级24/三级48磅左缩进；原生右对齐dot制表位按目录所在节实际正文宽度计算。右缩进预留18磅页码区，续行保持本级左缩进。原字体/字号/样式引用不动。明确局部spacing和ind覆盖原直接/继承旧值；未知方向、编号、字符单位或复杂栏仍保护。
- “保留原格式”不改目录几何；旧standard继续沿用原点线补齐语义，不重解释旧配置。项目恢复保留明确外观及收录策略，旧草稿缺少策略仍按原域收录。
- 新收录策略明确正文1–3级、摘要、后置独立标题和目录自身。按用户本轮最新更正，**新任务默认纳入目录自身**，排在Abstract之后；折叠设置和本地工作台均可关闭，旧保存的self=false不自动改成true。
- 摘要/后置标题从原确认角色取目标；已有目录已唯一链接、一级结构可靠的后置标题可继续收录，不因此给其普通格式或后续正文新增授权。目录自身只定位TOC域紧邻的明确“目录”标题，不做全文模糊搜索。逐段身份排序、去重；生成、Word计算和校验使用同一目标表。
- 非Heading标题用原生TC目录条目标记纳入（无可见结果），不改摘要/目录标题角色、字体、字号或大纲，不重编章节。不修改numbering.xml、分节、页码方案或页脚。目标书签、TC和目录结果均有精确反向保留校验。
- Word仍作隔离计算器，发布包从原包受限回填。最多4遍有界稳定性校验及最终文件只读重排，未稳定不发布。字典接口本轮实测：显式启用TC收录；macOS Word把默认C标识符序列化成裸`\f`并重排开关，只认可白名单等价语法，额外指令仍拒绝。
- 本地工作台可选外观、正文深度、摘要/后置标题、自身收录，继续原预演/采用；智能入口仍一次开始。新增策略存于现有本任务编辑草稿，项目保存恢复兼容；没有另建配置文件或模板体系。规则包原字段语义不变，目录几何/目标选项不伪装成学校规则或跨文档段号。
- 执行版本升级，原预演/在途结果按绑定失效。新增TC无缓存分隔是正常Word结构；原PDF冻结路径仅兼容受限TC指令，残缺REF等仍拒绝，没有新增PDF功能。

实现依据为[Microsoft TC字段说明](https://support.microsoft.com/en-us/word/field-codes-tc-table-of-contents-entry-field)和[TOC字段说明](https://support.microsoft.com/en-us/word/field-codes-toc-table-of-contents-field)。23.7磅和24/48磅来自用户给定参考论文样式，**不是已核实SCUT强制规范**。只读查看参考文件，没有导出其正文或衍生材料入库。

## 独立ZIP/XML核对

`scripts/verify_toc_policy.py`不导入新解析/生成器，用原始ZIP/XML和作者预期核对：原生制表位等于实际节宽、474twips/exact、0/480/960缩进；摘要i/Abstract ii/目录iii；链接目标唯一，目标按实际正文顺序且无重复。去除精确目录结果、必要目标书签及TC标记后，**其余正文和对象子树完全相同**；所有其他ZIP成员逐字节相同，包含关系、媒体、编号、样式、注释、页眉页脚。正式输出不是Word全量另存包。

公开输入/真实Word计算修正版及独立清单在[samples/phase57](../../samples/phase57/README.md)。演示原稿和第56阶段输入哈希不变，实际最终下载与另存副本同字节，Word观察关闭后哈希仍相同。

```sh
.venv/bin/python scripts/verify_toc_policy.py samples/phase57/source.docx samples/phase57/fixed.docx
.venv/bin/python scripts/run_offline_tests.py --pattern test_toc_policy.py
```

保留边界：只有原支持的安全TOC、可靠的标题/已有目标；锁定、绑定、复杂容器、标题结构冲突和不安全域保持并说明。保留外观不代表重设行距。非目录缩进、主题字体、标题重影、正文改写不在本轮。需要排除却仍被原Heading域直接命中的冲突对象会阻止对应更新，不通过改正文样式制造收录成功。普通修正副本仍可下载。没有Word时不声称真实页码已核验。8501收尾安全重启并健康检查，不修改Cloudflare。
