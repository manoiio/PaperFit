严格ID/字段/角色白名单、准确连续证据及本地冲突隔离；非法JSON、重复键、工具调用、空/截断仍整次拒绝。安全普通歧义可直接合入**待接受**范围摘要，不要求逐对象点击。人工分类差异、已确认范围、材料排除、封面/目录草稿对象、代码/数据和指令样线索不覆盖；复杂结构、继承的特殊/隐藏run亦不作为候选/上下文发送。basic只body/other/pending；extended沿原正文标题题注角色；academic沿原扩展集合，不自动切换或启用专门模块。

AI结构输出没有字体字号、用户确认或修正授权。接受合并摘要仍经原原子范围确认/检查；一键修正仍经原真实预演、白名单、读回复查、采用。没有修改core执行器或规则/项目格式。预演执行版本纳入新结构代码；不放开R33、复杂链接、字段、主题字体或页码限制。

缓存仅本会话一份，绑定实际发送内容、文件/任务、模式、规则/范围、模型/地址及提示词/执行版本。再次点击匹配结果复用；查看、筛选、检查、修正、下载不请求。范围变化后只保留不可采用的本会话历史。项目只保存原有已接受分类，**不保存结构请求、响应、缓存和授权**；恢复重新检查、0请求。显式诊断下载只含必要角色/ID、回执、usage和哈希，不含完整摘录。

已修正README、智能页、文档页、规范入口和AI包说明中“永不发送论文段落”的绝对说法。规范解析入口仍只发公开规范；结构入口会发送有限脱敏论文摘录。明显标签身份、长号码、邮箱及磁盘路径尽力隐藏，不承诺彻底匿名。

## 浏览器与实际文件

真实Chrome、1280×720及1440×900，无私有session_state注入。实际：选单文档扩展并上传 → 展开待发送内容 → 明确发送 → 查看回执/角色 → 再次点击缓存命中（0新增POST）→ 接受摘要检查 → 详细段落编辑纠正层级 → 重新核对检查 → 智能修正 → 实际下载DOCX及ZIP。

浏览器调试中原快捷分类控件的连续操作未等重运行完成，首次误保存为body，生成第1轮调试副本；随后通过完整文本分类编辑器明确保存heading2并核实，再从同一原稿生成第2轮最终副本（父轮仍原稿，不自动切输入）。这是实际失败/纠正记录，不能描述成只确认一次或只生成一轮。最终文件不采用该误分类。最终一条快捷命令执行48项格式记录、采用0次重复修正；5问题/12待复核继续保留。

独立原合法路径使用同一最终分类、规则、选择，其DOCX与**实际浏览器下载**逐字节一致；ZIP内fixed.docx与scope.json亦一致。原始ZIP/XML脚本核对全文逐字符顺序、所有未选部件字节、封面/代码/数据/指令段完整子树、指定正文12pt/2字符缩进及章节样式；源文件不变。第一次独立脚本将关键词必要run拆分造成的w:t分段变化误当文字变化，已改为逐段完整字符序列，并保留强部件/子树断言；只最终通过计为验收。

实际项目保存 → 只重启确认属于本项目的8501服务 → 浏览器导入ZIP → 核对摘要恢复 → 原范围重新检查。保留两轮历史，当前仍原稿；没有恢复AI缓存、旧预演或实时来源记录，未发请求。独立第二Chrome会话处理基础内置样本，实际DOCX仍与第40阶段合法样本逐字节一致，互不串范围/文件；动态入口仍默认关闭、未执行。

尝试额外浏览器在途换文件时，内置样本已有明确正文清单，所以0候选、发送禁用；没有第二次POST。该尝试及后续定位超时**不算在途API浏览器通过**。在途文件/模式/规则/人工草稿变化拒绝、网络超时/非法响应降级由受控transport和原生AppTest验证；不冒充真实网络故障。真实调用未验证这两个特殊时序/故障场景，这是剩余浏览器验收限制。原有范围变化使报告/选择失效已由真实人工纠正流程观察。

## 操作与限制

相同8对象最终分类可用原批量入口按body/heading1/heading2分3组指定。AI路径需要人工指定的对象只剩1个层级；但本轮真实浏览器含2次人工保存（含一次定位失误）、3次范围检查、2次明确修正，不能证明总点击或总耗时减少。没有据此计算提速百分比。收益是7项结构建议直接参与原范围/检查/修正，用户无需逐项录入这7项；无编号层级仍需核对。独立合法修正脚本本地耗时见independent.json；与网络/人工阅读时间分开，不当用户端总时间。
